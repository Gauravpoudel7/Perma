# CHANGELOG POLICY: PERMA

## Format
All changes are recorded in `docs/CHANGELOG.md` using a simplified Keep a Changelog format.

## Categories
- **Added**: For new features (e.g., "Added Long minting").
- **Changed**: For changes in existing functionality (e.g., "Updated solvency formula").
- **Fixed**: For bug fixes (e.g., "Fixed rounding error in premium settlement").
- **Removed**: For deprecated features.

## Entry Standard
Each entry must include:
- **Date**: YYYY-MM-DD.
- **Version/Tag**: (e.g., `v0.1.0-alpha`).
- **Description**: A clear, concise summary of the change.
- **Impact**: Which components or docs were affected.

## Workflow
1. Developer adds a changelog entry in the same PR as the code change.
2. The `PR-CHECKLIST.md` requires a "Changelog updated" checkbox.
